Вахрушев И.А., группа 25-КМ-ИБ2

На этом Mac всё установлено и проверено.

1. Дважды нажми «Запустить ПЗ4.command».
2. Дождись сообщения о готовности. Откроется Kafka UI:
   http://127.0.0.1:8088
3. Открой Postman. Коллекция «Шарай ПЗ4 — Kafka HAProxy RabbitMQ» уже импортирована.
4. Выбери коллекцию → Run → Local → 1 iteration → Start run.
   Должно быть 16 запросов, 32 Passed, 0 Failed, 0 Errors.
   Выполняй всю коллекцию по порядку. Перед чтением Consumer предусмотрено ожидание
   1,8 секунды: в задании обработка каждого сообщения занимает одну секунду.
5. Kafka UI → Topics → orders → Messages: сообщения остаются в журнале Kafka.
   Рабочие топики: orders (3 партиции), notifications (1), errors (1).
6. Для освобождения 4 ГБ памяти дважды нажми «Остановить ПЗ4.command».

Другие адреса:
Producer Swagger: http://127.0.0.1:8020/docs
Consumer Swagger: http://127.0.0.1:8021/docs
RabbitMQ: http://127.0.0.1:15672
Пользователь RabbitMQ: lab. Пароль хранится в локальном файле .env этой папки.
Не отправляй .env преподавателю и не добавляй его в Git.

Для редактирования открой папку в VS Code. Код исполняется в Docker внутри
виртуальной машины sharay-messaging, а не в Python macOS.
GitLab из второй работы запускать не нужно.

После перезапуска Consumer его списки в памяти начинаются заново. Данные брокеров
и offsets Kafka остаются в Docker-томах. Для новой проверки снова запусти коллекцию:
она публикует новые сообщения и проверяет их получение.

Что в проекте:
docker-compose.yml — сервисы, зависимости и порты;
haproxy.cfg — входной TCP-порт 9093 и адрес Kafka 9094 внутри Docker;
producer_service/main.py — HTTP-запросы и публикация в Kafka/RabbitMQ;
consumer_service/main.py — чтение, задачи обработки и подтверждения;
verify_and_benchmark.py — функциональная проверка и измерение задержек;
Messaging.postman_collection.json — готовая коллекция запросов;
evidence/ — фактические результаты и журналы;
Скриншоты/ — настоящие снимки Kafka UI, RabbitMQ и Postman.

Основа из методички: два FastAPI-сервиса, заказ Laptop, уведомление,
топики orders/notifications, Kafka UI и HAProxy.
Дополнено по самостоятельным заданиям: errors, отдельные задачи с задержкой 1 с,
аналогичная передача через RabbitMQ и сравнение задержек.
Для запуска в Docker настроены адреса сервисов, Kafka advertised.listeners,
KRaft и права тома. .dict() заменён на model_dump().

Работа использует контейнеры Kafka 3.9.1, Kafka UI 0.7.2, HAProxy 3.0.12,
RabbitMQ 4.1.0. Сравнение проводилось в одной ВМ после трёх прогревочных пар:
20 сообщений на брокер. Измерялась доставка до начала обработки, без задержки 1 с.
Среднее: Kafka 4,869 мс; RabbitMQ 2,030 мс.
Пять сообщений Kafka с обработкой по 1 с завершились за 2,018 с;
максимум одновременно обрабатывались четыре сообщения этой серии.
